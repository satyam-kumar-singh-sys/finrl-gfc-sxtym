# SUBMISSION — how the AI4Finance Open Trading Challenge actually works

*Checked 12 November 2026 against <https://ai4finance.org/competition>, the
AI4Finance Discord and the challenge repository. Read the "What is genuinely
unclear" section at the bottom before you wait for a deadline that may not exist.*

---

## 1. The rules, restated

| Item | Requirement |
|---|---|
| Season | **Pilot Quarter**, status **Open**, rolling — no fixed entry deadline is published |
| Framework | **Must** use the official **FinRL-Trading / FinRL-X** repository; modifications to agents/rewards allowed |
| Execution | **Alpaca Paper Trading** only. *"No mock data or simulated environments"* |
| Minimum period | **30 trading days** of live paper trading |
| Reproducibility | Public GitHub repo, `requirements.txt`, fixed random seeds where applicable |
| Transparency | Trade logs, **daily equity curve**, no manual intervention during execution |
| Scoring | Risk-adjusted return (Sharpe/Sortino) **30%** · max drawdown **20%** · stability **20%** · documentation **15%** · code quality **15%** |
| Prizes | $3,500 / $1,000 / $500, paid as scholarships/research grants |
| Entry package | **repo link + equity curve + description** |

This repository satisfies each line: public repo, `requirements-live.txt` and
`requirements.txt`, deterministic strategy (seeded tests), `logs/` + `results/`
committed by the trading workflow, and no manual step during the live period.

## 2. Where to register and submit

The competition page does **not** host a registration form. Its three calls to
action are: *Get Challenge Template* (→ GitHub repo), *Join Discord*, and a
*Submit* step described only as "submit your repo link, equity curve, and
description". The `Join Discord` button and the "Submit" anchor both point to the
same Discord invite, so **Discord is the intake channel in practice**:

1. **Join the AI4Finance Discord** → <https://discord.gg/trsr8SXpW5>
   (permanent invite used by the foundation; the same link is in the
   FinRL-Trading README).
2. Read the challenge/rules channel, then **post your entry** in the
   challenge-submissions channel (it is named something like `#trading-challenge`,
   `#competition` or `#submissions` — pick the one that matches). If you cannot
   find one, post in the general channel asking where pilot-quarter submissions
   should go; the maintainers (Bruce Yang is the maintainer of FinRL-Trading) are
   active there.
3. **Also email the same package to <contact@ai4finance.org>** with the subject
   `AI4Finance Open Trading Challenge — Pilot Quarter entry — <your name>`.
   Two channels is the right amount of redundancy for a rolling challenge with
   no form.
4. Optional but useful: open a **Discussion** in your own repo echoing the entry
   (acts as a permanent timestamped record).

## 4. What "equity curve" should mean

Two acceptable artifacts, and this repo produces both:

* `results/daily_equity.csv` — one row per session taken **after the close**
  (`date_ny, equity, cash, long_market_value, last_equity, daily_return`).
  This is the machine-readable curve.
* `figs/live_equity.png` — the same curve plotted against SPY, with drawdown.
  Generated by `python -m scripts.report` (it can also rebuild the curve
  straight from the broker with `--from-alpaca`, so a missed workflow run does
  not leave a hole).

Include the **backtest** curve too (`figs/ata_equity.png`) — judges usually want
to see out-of-sample truth next to the in-sample claim, and STRATEGY.md already
states the honest expectation (live Sharpe ≈ 0.4, not the backtest's 0.55).

## 5. Timeline that satisfies the 30-trading-day rule

| Day | What happens |
|---|---|
| Day 0 | repo public, keys in GitHub secrets, workflow enabled, first paper orders |
| Day 1–29 | the Action trades and commits logs automatically; you watch, do not touch |
| Day 30+ | `python -m scripts.report` → `results/live_summary.md`; send the entry text above |
| After | keep it running — "stability" is 20% of the score, so a longer, uninterrupted record is strictly better |

With ~21 trading days per month, expect 6–7 calendar weeks *if* you start from
zero. Since the challenge is rolling, there is no reason to wait for a cohort —
starting earlier strictly dominates.

## 6. What is genuinely unclear (and how to resolve it in one Discord message)

The published page has no form, no deadline and no explicit registration step.
Rather than guess, ask this in Discord and by email — it takes one message and
removes all ambiguity:

> "Hi — I'm preparing an entry for the Pilot Quarter of the Open Trading
> Challenge (FinRL-Trading + Alpaca paper, automated via GitHub Actions,
> live since <date>). Two questions: (1) is there a registration form, or is a
> Discord post plus email the intended submission? (2) is there a cut-off date
> for this quarter's evaluation, or is it rolling? Thanks!"

Two other things worth confirming at the same time:

* whether the **paper account must be created with the same email** you use to
  submit (helps them tie the equity curve to the entrant);
* whether they want the Alpaca **account ID** so they can verify fills
  themselves (offer it — it demonstrates transparency).

## 7. Do-not-do list

* Do not trade a live (funded) Alpaca account — the rules say paper, and this
  repo hard-refuses non-paper endpoints.
* Do not hand-trade during the live period; "no manual intervention" is a stated
  requirement and every deviation is visible in the logs.
* Do not rewrite the strategy midway and present it as one continuous record —
  restart the clock and note the change in `CHANGELOG.md`.
* Do not commit `.env`, API keys or secrets (`.gitignore` already covers them).
* Do not quietly delete losing days from the equity curve. The broker history is
  the ground truth and they can ask for it.
