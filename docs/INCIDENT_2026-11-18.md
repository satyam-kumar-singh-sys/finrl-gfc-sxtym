- 44228020286, 03:06:18 UTC: live-paper-trading failed at Pre-flight checks.
- Both alert jobs succeeded and recorded one incident in issue #2.

- External snapshot heartbeat at 21:20 UTC on November 17 succeeded and saved

Public job metadata identifies the failing step, but annotations only report
exit code 1, not pytest's detailed output. Running the deployed checkout locally
reproduced exactly one failure: test_dashboard_status_badge_reflects_files.

## Root cause reproduced

The test used a fixed November 12 snapshot and the real current UTC clock,
expecting LIVE. Production correctly considers snapshots older than five days
STALE, so the test begins failing on November 18. This was a test fixture bug,
not a broker failure. The pre-flight gate prevented those failed runs from
reaching either rebalance or snapshot steps.

## Patch

Freeze the dashboard clock in the fixture; do not alter production behavior.
Add six cases proving the 0/5/6-day boundary in 2026 and 2030. Full suite: 79 pass.
No strategy, runner, guard, account, baseline, cron or execution changes.

## Remaining limitations, not silently bundled into this fix

GitHub scheduled triggers have been very late. A broker-clock execution gate
before any order submission remains advisable, but would modify run_daily.py,
which is part of the declared fingerprint. Do not bundle that execution change
into a test fix or silently replace the evaluation baseline. If adopted, record
it explicitly and review the freeze-window claim.

Weekend heartbeat rows exist historically; they must not be counted as US
trading sessions. Keep external job schedules weekday-only in UTC. Current public
logs cannot establish whether the external service's configuration was corrected.

Existing reports include duplicate and setup rows, and no audited 30-session
eligibility counter is implemented. Health green is operational evidence, not an
eligibility certificate. Snapshot/report timing needs separate improvement if
an official regular-session-close valuation is required.
